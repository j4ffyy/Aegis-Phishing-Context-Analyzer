# Functional Requirements Re-scoping Audit: FR01 and FR08 (E-29)

- **Evidence ID:** E-29
- **Produced By:** I-17 / Revision Matrix Row 25 & Row 16 Alignment
- **Commit:** `a482063`
- **Specification:** AEGIS Implementation Plan v3.2 §4.2, §7 (I-17) & Post Defense Verdict Item 12

---

## 1. Context and Panel Finding

In the Capstone 2 defense verdict (Item 12), the panel found:
> *"Gmail scope, shared accounts and warning-only behavior: Paper overstates implementation scope: claims Gmail integration while defense confirms only browser-based overlay with no actual Gmail integration. This violates FR01 (Email Ingestion) and FR08 (User Alert) as the system does not interact with Gmail's internal mechanisms but operates as a standalone browser extension. The defense explicitly states: 'Aegis operates strictly as a client-side analysis and decision support overlay' and 'as a browser extension' with no Gmail integration beyond the DOM."*

In accordance with Plan §2 and Revision Matrix Row 25, FR01 and FR08 are **not removed** from Chapter 3 Table 7 (Functional Requirements), but are formally **re-scoped and rewritten** to reflect what the software actually implements.

## 2. Requirement Re-scoping Specification

### FR01: Email Ingestion vs. DOM Content Observation

| Field | Original Manuscript Text (Ch. 3 Sec. 3.2 Table 7) | Revised Approved Text (Revision Matrix Row 25) |
|---|---|---|
| **Requirement Identifier** | `FR01` (Email Ingestion) | `FR01` (Email Content Observation) |
| **Specification** | *"The system shall ingest incoming email messages directly through integration with the Gmail webmail interface / API, extracting headers, body content, hyperlinks, and attachment payloads for security analysis."* | *"The system observes email content rendered in the active Gmail browser DOM through a client-side `MutationObserver`. It operates strictly as an ephemeral browser extension and does NOT interact with Gmail's internal APIs, IMAP/POP3 protocols, server-side mail storage, or transport agents."* |
| **System Boundary** | Overclaimed native API / Mailbox Ingestion | Ephemeral client-side DOM reader (`content_script.js`) |
| **Implementation Reality** | Verified in `content_script.js` L40–L120: MutationObserver watches `#\:*` email bodies and extracts visible DOM elements. |
| **Architectural Status** | Disavowed | Formally Adopted |

### FR08: User Alert vs. Advisory Risk Notification

| Field | Original Manuscript Text (Ch. 3 Sec. 3.2 Table 7) | Revised Approved Text (Revision Matrix Row 25) |
|---|---|---|
| **Requirement Identifier** | `FR08` (User Alert & Quarantine) | `FR08` (Advisory Risk Notification) |
| **Specification** | *"The system shall alert the user and automatically quarantine suspected phishing emails to prevent user interaction until administrative review."* | *"The system displays an advisory risk assessment overlay within the Gmail browser interface upon user email selection (triggered with a 300ms debounce on DOM mutation). It displays a color-coded risk badge (Safe, Warning, Critical) and plain-language Explainable AI (XAI) rationale; it does NOT alter mailbox state, delete emails, block navigation, or execute automated server quarantine."* |
| **System Boundary** | Overclaimed Automated Quarantine / Mailbox Alteration | Advisory Client-Side Decision Support Overlay (`overlay.js`) |
| **Implementation Reality** | Verified in `overlay.js` L20–L150: Inserts Shadow DOM container displaying risk drawer and modal; zero mailbox manipulation. |
| **Architectural Status** | Disavowed | Formally Adopted |

## 3. Impact on Remaining Functional Requirements (FR02 – FR07)

1. **FR02 (Syntactic Heuristics):** Unchanged. Operates on extracted payload via rule-based keyword, typosquatting, and attachment heuristics.
2. **FR03 (Machine Learning Ensemble):** Unchanged. Operates on tabular feature vector via RF + XGBoost.
3. **FR04 (Deep NLP Context Analysis):** Unchanged. Evaluates subject + body text via DistilBERT ONNX.
4. **FR05 (Behavioral Baseline Tracking):** Clarified. Operates strictly in browser client memory / `chrome.storage.local` per workstation.
5. **FR06 (Threat Intelligence Integration):** Unchanged. Queries VirusTotal v3 API with rate-limiting and local caching.
6. **FR07 (Explainable AI Rationale):** Unchanged. Generates plain-language bulleted summaries explaining multi-layer risk factors.

## 4. Manuscript Integration Directives

1. **Chapter 1 (Section 1.3 & 1.4):** Update project scope to explicitly disclaim native Gmail API integration and automated mailbox quarantining.
2. **Chapter 3 (Section 3.2, Table 7):** Replace FR01 and FR08 rows with the revised wording above. Add footnotes citing ephemeral DOM boundary.
3. **Chapter 4 (Section 4.1 & 4.2):** Clarify that all user alerts function as client-side decision support overlays and do not alter shared mailbox state.
